# 视觉评审

> 守卫只能拦住规则能写清的错误（色值、字号、原生控件）。好不好看、顺不顺手要靠截图评审。新页面或明显的 UI 改动交付前都走一遍。

## 1. 截图

每个改动页面截 4 张：

| 宽度 | 浅色 | 深色 |
|---|---|---|
| 1280 | ✓ | ✓ |
| 375 | ✓ | ✓ |

读写数据的页面另外把加载、空、失败各过一遍（按 [页面状态规范](states.md)）。

## 2. 对照

- **Kit**：同类组件、同类页面样板（`src/pages/examples/`）长什么样，新页面就该长什么样。
- **参考产品**：用 Mobbin 搜同类界面（例如「settings page」「empty state」），挑 2-3 个做得好的对比层级和间距。参考对象写进评审记录。

## 3. 检查清单

**结构**
- 用了 `Page` / `PageHeader` / `Section`，宽度档位选对
- 每屏只有一个主按钮，在页头最右或表单末尾
- 信息层级不超过三层（页标题、区块标题、内容）

**对齐与间距**
- 同一列元素左边缘对齐在一条线上
- 同级元素间距一致；控件高度一致（`h-9`，小号 `h-8`）
- 没有元素贴着卡片或屏幕边缘

**文字**
- 关键信息没有被截断；截断处有完整内容可看（tooltip 或详情）
- 没有解释性副标题和重复说明
- 数字用 `tabular-nums`，数字列右对齐

**状态与交互**
- hover、焦点环可见；禁用态能看出为什么不可用
- 加载、空、失败、提交中都有对应表现

**主题与响应式**
- 深色下没有白底块、看不清的文字或边框
- 375 宽下没有横向滚动，按钮和输入框没有被挤变形

**同屏对比**
- 新加的元素与同屏已有元素相比，不更大、更重、更抢眼

## 4. 记录

问题按下表列出，写进提交说明或 PR 描述。「必修」修完才算交付，「建议」记下来下一轮处理：

| 级别 | 位置 | 现象 | 依据 | 修法 |
|---|---|---|---|---|
| 必修 | 列表页 · 页头 | 375 宽下标题被压成「供…」 | 文字 · 关键信息截断 | 标题不收缩，操作区换行 |

- **必修**：违反 DESIGN.md / 组件 / 骨架 / 状态规范，或功能状态缺失、主题或窄屏下不可用。
- **建议**：规范之内但可以更好，例如层级可以再收敛、参考产品有更顺的做法。

# 页面状态规范

> 每个读数据或改数据的界面都要覆盖下面的状态。组件见 [组件规范](components.md)，样例见 Kit「状态」区。

## 选用

| 状态 | 场景 | 做法 |
|---|---|---|
| 首次加载 | 还没有任何数据 | 300ms 内不显示指示；超过后用 `Skeleton` 按真实布局占位。不用整页 Spinner |
| 刷新 / 翻页 | 已有旧数据 | 保留旧数据，在触发位置显示 `Spinner`，不闪回骨架屏 |
| 提交中 | 点了保存、生成、删除 | 按钮 `disabled` + `Spinner` + 进行时文案（「保存中」），防重复提交 |
| 空：从未有数据 | 新用户、新项目 | `Empty`：图标 + 标题说明这里放什么 + 创建第一个的主操作 |
| 空：筛选无结果 | 搜索、筛选后为空 | 一行 `text-muted-foreground`「没有匹配的 X」+ 清除筛选。不用 `Empty` |
| 加载失败 | 区块数据拿不到 | 区块内 `Alert variant="destructive"`：标题「X 加载失败」+ 原因 + 重试按钮。不用 toast |
| 表单校验失败 | 字段不合法 | `Field` 的 `error` + 控件 `aria-invalid`；提交时聚焦第一个错误字段。不用 toast |
| 操作成功 | 结果在界面上直接可见 | 不提示 |
| 操作成功 | 结果不可见（后台任务、复制、跨页） | `toast.success`，一句短句 |
| 操作失败 | 非表单操作出错 | `toast.error`：原因 + 能重试时带「重试」action |
| 不可撤销操作 | 删除、覆盖、断开 | `AlertDialog`：标题写动作和对象，说明写后果，确认按钮写动词并用 `destructive` |

## 文案

- 错误写发生了什么 + 怎么办：「网关连接失败，检查地址后重试」。不写「出错了」「糟糕」，不道歉。
- 确认弹窗标题用问句写动作和对象：「删除 3 个供应商？」；按钮写动词「删除」，不写「确定」。
- 成功提示只写结果：「已复制」「已保存到资产库」。
- 进行时文案用「中」：「保存中」「生成中」。

## 守卫

- 禁用 `window.alert` / `confirm` / `prompt`，分别改用 `toast`、`AlertDialog`、`Dialog` + `Input`。

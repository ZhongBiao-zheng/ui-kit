# 界面开发流程

> 从需求到上线的界面工作顺序。每一步的产出写在括号里。

## 1. 定页面（页面清单）

一句话写清需求，列出要做的页面，每页标注套哪个样板：设置页、列表页、详情页（见 [页面骨架规范](layouts.md)）。

## 2. 找参考（参考列表）

用 Mobbin MCP 搜每个关键页面的同类界面，每页挑 3-5 个，记下 Mobbin 链接和要学的点（层级、信息密度、交互方式）。搜索词写界面类型加产品类型，例如「productivity tool settings page」。

## 3. 出稿（选定的设计稿）

在 Claude Design 里出稿：给需求、页面清单和参考截图，让它自由发挥，不套本规范的 token。每个关键页面出 2-3 个方向，选定一个。

## 4. 映射到规范（实现清单）

把选定稿拆成本规范的组件和样板：

- 能用现有组件表达的，照组件实现，不照抄稿子的像素值。
- 稿子里出现规范没有的颜色、字号、组件：先判断是否值得进规范。值得的，改 ui-kit 仓库（DESIGN.md 或 `components/ui`）并发布，项目里再 `shadcn add` 拉取；不值得的，按现有规范实现。不在页面里临时写。

## 5. 实现与验收（可交付的页面）

1. 按 [页面状态规范](states.md) 覆盖加载、空、失败。
2. `pnpm lint && pnpm test` 通过。
3. 给新页面写 Storybook story（页面用 `PAGE_MODES`）。
4. 按 [视觉评审](review.md) 截图评审，必修项修完。
5. Chromatic 接受新快照作为基线。
